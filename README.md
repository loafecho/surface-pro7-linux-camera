# surface-pro7-linux-camera

Kernel and userspace patches that get the Surface Pro 7's front, rear and IR
cameras and its touchscreen driver working on Linux, the fault-injection
scripts used to prove the touchscreen fixes, and two small offline checkers
that hold the patch series and the test evidence to a fixed standard.

Author: Tony Garcia ([loafecho](https://github.com/loafecho)).

## Why it exists

On the Surface Pro 7 with a linux-surface kernel, the IR camera's receiver
lane was never configured, so it saw no data; the rear camera failed most
stream starts while its lens kept the sensor powered; and the touchscreen
driver (`ipts`) could fault in a start-up race. After that fault, every later
reboot, power-off or module unload hung, because the driver's stop path waited
forever.

The work here went from working patches to upstream-shaped series. Most of the
investigation and patch writing was done with an AI coding assistant, so the
repository is also built around one question: how do you make that kind of
work checkable? Every claim in a cover letter points to a test record, the
records are written only by scripts whose hash goes into each record, and a
checker recomputes the verdict from the raw lines instead of trusting the
summary.

## What is here

| Path | What it is |
|---|---|
| `patches/` | The first working patches (kernel 6.19.8 era): camera sensors, the out-of-tree IPU4P driver, libcamera, PipeWire, plus container build steps. See `patches/README.md`. |
| `series/` | `git format-patch` series prepared for upstream review: `ipts-rfc/` (touchscreen, with cover letter), `libcamera/`, `ipu4p/`. Status of each in `series/README.md`. |
| `fault-injection/ipts-fault-inject.patch` | Test-only, add-only patch for the ipts driver. Built only with `-DIPTS_FAULT_INJECT`. `fault=3` starts a kernel thread that takes the driver's message lock and exits holding it. |
| `fault-injection/device/` | Reproducers that run as root on the device: the start-up race (`ipts-race.sh`), unload while the touch device is in use (`ipts-unload-race.sh`), and the suspend hook reload loop (`ipts-hook-stress.sh`). |
| `fault-injection/host/` | Campaign drivers that run on a second machine over SSH: the F3 campaign (`campaign-v2.sh`), a read-only device check (`device-check-v2.sh`), a multi-run unload campaign that reboots through firmware stalls, a timed reboot, and a fault-then-sleep-then-reboot test. |
| `fault-injection/deadman/` | `sp7_deadman`, a small kernel module that arms a timer from a top-priority reboot notifier. If a driver hangs in its shutdown path, it dumps the blocked tasks and panics (record in pstore) or restarts the machine. Standard watchdogs are stopped before `device_shutdown()`, so they cannot catch that hang. |
| `camcheck/` | `sp7-camcheck.sh`, the on-device camera regression suite (stress starts on front and rear, frame capture, browsers through PipeWire, IR open/stream/close cycles), with its Python helpers. |
| `evidence/ipts-f3/` | The recorded F3 campaign (3 cycles) and device check from 2026-10-27, in the "ipts-evidence v1" format. The host line is redacted. |
| `tools/seriescheck.py` | Offline patch lint. See below. |
| `tools/evidencecheck.py` | Evidence checker. See below. |
| `tests/` | pytest suite and text fixtures for both checkers. |

## How the checkers work

`tools/seriescheck.py` reads a folder of `NNNN-*.patch` files (or one patch)
and checks, without a kernel tree:

- every hunk's line counts match its `@@` header, and the diffstat matches the diff;
- the `[PATCH n/m]` numbering is complete and agrees with the file names;
- no `To:`/`Cc:`/`Bcc:` headers, and no email address outside an allowed pattern in the headers or message;
- the subject has a `subsystem: ` prefix and fits in 75 characters;
- each patch discloses AI assistance (an `Assisted-by:` trailer, or a sentence in the body where the project's tooling rejects that trailer);
- Signed-off-by comes only from the named signer (a missing one is a NOTE: only the submitter adds it);
- optionally (`--add-only`) the patch only adds lines, and (`--rules d5`) no added line pins the module, loops forever, uses a lock-loss heuristic, waits on a completion without a timeout, or calls `disable_work_sync()`.

`tools/evidencecheck.py` reads "ipts-evidence v1" files and recomputes each
cycle's outcome from its fields. It fails when the SUMMARY line disagrees with
the CYCLE lines, when a boot ID is not in the device's boot journal, when an F3
cycle did not fire the fault, took longer than 30 s to unload, or left a task
blocked in the HID core, or when the device check did not report its manifest OK.

Each check has a fixture that must fail it and a fixture that must pass, under
`tests/fixtures/`. The fixtures are generated by `tests/fixtures/make_fixtures.py`,
and a test fails if the committed fixtures and the generator drift apart.

## How to run it

Checkers and tests need only Python 3.10 or newer and pytest:

```sh
python3 tools/seriescheck.py series/ipts-rfc series/libcamera series/ipu4p
python3 tools/seriescheck.py --plain --add-only --rules d5 fault-injection/ipts-fault-inject.patch
python3 tools/evidencecheck.py evidence/ipts-f3
python3 -m pytest -q
shellcheck -S warning $(git ls-files '*.sh')
make -C fault-injection/deadman      # needs kernel headers for the running kernel
```

CI (`.github/workflows/ci.yml`) runs all of the above on every push, plus
`ruff`, and builds the deadman module against the runner's kernel headers.

The device and host scripts need a Surface Pro 7 running a kernel with these
patches, root on the device, and SSH from a second machine. Host scripts read
the device address from `SP7_HOST` (for example `SP7_HOST=user@192.0.2.10`).
They load and unload kernel modules, inject faults and reboot the device. Run
them only on a test machine, with the deadman module loaded and
`kernel.panic` set above 0 (`campaign-v2.sh` refuses to start otherwise).

## What was tested

From the cover letter in `series/ipts-rfc/`, on one Surface Pro 7 (kernel
6.19.8, the series code plus the test-only fault patch):

- Before the fix, the stock driver faulted in the first start-up race cycle in 4 of 4 runs.
- With both patches: 200 of 200 start-up race cycles and 200 unload-under-load cycles with 0 kernel errors (2 runs ended in a firmware stall that needs a reboot), 50 of 50 suspend/resume cycles, and 10 of 10 normal restarts back within 90 s.

Those runs' raw logs are not in this repository; the F3 campaign in
`evidence/ipts-f3/` is. The camera numbers in `series/README.md` come from the
same machine.

## Limits

- One device. Nothing here was run on another Surface model or on EDS1 touch hardware.
- Patch 2 of the ipts series has a known use-after-free and is on hold; see the cover letter.
- No series has been posted upstream, and no patch has a Signed-off-by.
- The libcamera series was not built on libcamera `master`; the working patches in `patches/` target older trees and may not apply to current ones.
- `seriescheck.py` is a structural lint. It does not run `checkpatch.pl`, apply patches to a tree or build anything. The original checker also built the driver against a kernel tree and read live facts from the device over SSH; those gates are not included.
- The evidence files record the hash of the scripts that wrote them. The scripts in this repository were edited afterwards (device address moved to `SP7_HOST`, paths generalized), so their hashes no longer match the recorded ones.
- The F3 evidence covers 3 cycles.
